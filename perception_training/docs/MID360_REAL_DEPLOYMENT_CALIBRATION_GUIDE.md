# MID360 实际无人机部署：数据准备与标定指南

## 1. 文档目的

本指南用于后续将当前 SA-UMNet 感知模型部署到搭载 Livox MID360 的真实无人机时，指导真实数据采集、传感器标定、输入分布统计和部署验收。

当前模型已经完成保存、TorchScript 导出和仿真测试。真实 MID360 数据统计与标定不是为了“再次保存模型”，而是为了降低仿真与真实传感器之间的差异（sim-to-real gap），避免扫描轨迹、噪声、漏点、外参或时间同步误差导致真实部署性能下降。

如果系统只用于仿真，可以暂时跳过本流程；如果需要真实无人机部署，建议按本文执行。

## 2. 信息安全要求

1. 禁止将本地电脑中的任何文件或代码上传到 AutoDL。
2. 真实数据应在连接 MID360 的采集设备上生成。
3. 数据进入 AutoDL 前，必须通过公司批准的传输、脱敏和存储流程。
4. 不在文档或日志中记录设备密码、访问令牌及其他敏感信息。
5. 原始数据应只读保留，处理结果另存，禁止覆盖原始 bag。

## 3. 需要记录的数据

优先记录原始 ROS bag，而不是只保存处理后的二维栅格或截图。

每个采集包应尽量同步包含：

- MID360 原始点云，优先保留 Livox CustomMsg。
- 每个点的 x、y、z、反射强度和点级时间偏移。
- Livox tag、line 或驱动提供的有效性字段。
- IMU 角速度、线加速度和时间戳。
- 飞控、里程计或定位系统的位姿和速度。
- 动态目标实验的参考距离、方向和大致速度。
- 雷达安装位置、安装方向、离地高度及场景说明。
- 雷达序列号、固件版本、驱动版本、工作模式和时间同步方式。

不要只采集很短的数据。MID360 使用非重复扫描，过短的采集不能充分反映真实覆盖率和漏点规律。

## 4. 建议采集场景

| 场景 | 建议采集量 | 用途 |
|---|---:|---|
| 雷达静止、前方空旷 | 3–5 分钟 | 虚假回波、远距离有效性 |
| 平整墙面 | 2、5、10、20、30 m 各 1–2 分钟 | 距离偏差、噪声与角度分布 |
| 雷达静止、环境静止 | 至少 3–5 个场景 | 扫描覆盖率、漏点和强度分布 |
| 雷达运动、环境静止 | 慢速、正常速度各 3–5 分钟 | 运动畸变与时间同步 |
| 无人机原地偏航、俯仰和横滚 | 每种动作多次 | 外参与时间偏移检查 |
| 行人横穿、接近、远离 | 每种至少 20–30 次 | 动态掩码和径向速度评估 |
| 车辆或较高速目标 | 条件允许时采集 | 高速目标泛化能力 |
| 室内、室外、强光、弱反射表面 | 每类若干段 | 环境泛化和极端条件评估 |

采集时应覆盖网络实际使用的近、中、远距离，并包含静态、普通动态和困难动态场景。

## 5. 推荐数据目录

数据通过公司合规方式进入远程服务器后，建议存放为：

```text
/root/autodl-tmp/MID360_real/
├── raw_bags/          # 原始数据，只读保留
├── scene_metadata/    # 场景、距离、目标和设备信息
├── calibration/       # 外参、时间偏移及标定结果
├── processed/         # 转换后的点云或网络输入
├── statistics/        # 输入分布统计
└── reports/           # 图表和验收报告
```

每段 bag 应有对应的元数据文件，至少记录日期、地点类型、场景类别、动作、天气/光照、设备配置和异常情况。

## 6. 标定流程

### 6.1 坐标系约定

首先确认并记录：

- MID360 原始坐标轴方向。
- 无人机 body 坐标轴方向。
- 感知模块使用的坐标轴方向。
- 距离单位、角度单位和速度正负方向。
- 从雷达到机体的变换方向。

目标是得到雷达到机体的刚体变换：

```text
T_body_lidar = [R_body_lidar, t_body_lidar]
```

其中平移包含 x、y、z，旋转包含 roll、pitch、yaw。必须明确矩阵是 lidar 到 body，避免在程序中误用逆变换。

### 6.2 外参标定

1. 精确测量雷达相对机体中心或飞控基准点的安装位置。
2. 在包含地面、平墙和明显几何结构的静态环境采集数据。
3. 使用测量值作为外参初值。
4. 将点云变换到 body 或世界坐标系，检查地面是否水平、墙面是否垂直。
5. 让无人机或安装平台执行偏航、俯仰和横滚，检查点云是否重影或漂移。
6. 必要时使用雷达—IMU联合标定工具优化旋转、平移和时间偏移。
7. 保存最终矩阵、欧拉角、工具版本、输入数据和残差报告。

验收时，静态平面应稳定且无明显双层；平台转动后，同一静态结构不应产生系统性漂移。

### 6.3 时间同步标定

需要确认：

- 雷达、IMU和飞控是否共用统一时钟。
- 点云消息时间戳表示帧起点、终点还是其他时刻。
- 点级时间偏移是否保留且单位正确。
- 雷达与 IMU/里程计之间是否存在固定时间差。
- 系统时间同步方式是 PTP、PPS、硬件同步还是软件时间。

检查方法：

1. 采集静止数据，确认时间戳连续且严格递增。
2. 执行较快的往复转动。
3. 使用 IMU 运动补偿点云。
4. 调整时间偏移，寻找静态墙面或边缘重影最小的位置。
5. 将最终偏移量和时间戳语义写入标定文件。

时间未同步会把机体运动误认为目标运动，直接影响回波差分、动态分割和径向速度估计。

### 6.4 距离与噪声统计

使用不同距离的平墙数据统计：

- 测量距离的均值、偏差和标准差。
- 噪声随距离和入射角的变化。
- 异常远点、近点和无效点比例。
- 不同距离的有效回波率和漏点率。
- 反射强度随距离、材质和角度的分布。

MID360 通常不需要用户重新标定厂家内部光学参数。本项目所说的“标定”主要是外参、时间同步以及真实输入统计。

### 6.5 扫描和覆盖率统计

统计不同积累时长下的：

- 每帧点数及其波动。
- 方位角和俯仰角覆盖。
- 每个感知栅格的命中次数。
- 空白栅格比例和回波掩码。
- 首次命中、最近命中及多点落入同一单元的分布。
- 静态场景中伪动态响应和伪径向速度。

这些结果用于调整仿真器的扫描轨迹、点数、噪声、漏点和积累窗口，之后再决定是否生成最终 120K 数据。

## 7. SA-UMNet 输入一致性检查

将真实点云送入当前预处理流程后，逐项核对网络四通道的定义、单位、归一化和有效范围。最终应以代码中的输入构造实现为准，不允许根据名称猜测。

重点检查：

- 输入张量形状与训练时完全一致。
- 距离和速度单位是否分别为 m 和 m/s。
- 方位角、俯仰角和栅格排列顺序是否一致。
- 无回波单元是否生成正确的回波掩码。
- 首帧 history_valid 是否为 false。
- 历史帧间隔和点级时间补偿是否正确。
- NaN、Inf、无效点和越界点是否按训练方式处理。
- 每个通道的均值、标准差、分位数和饱和比例是否接近仿真训练集。

若真实数据明显超出训练分布，应先修正预处理或仿真参数，不应直接依赖调整 mask threshold 掩盖输入问题。

## 8. 动态场景验证

动态目标应至少覆盖横穿、接近和远离三类运动。建议记录真实或近似参考速度，并计算：

- Mask IoU、F1、Precision、Recall 和 FPR。
- 近、中、远距离分层 IoU。
- 径向速度 MAE 和偏差。
- 风险目标保留率。
- 静态背景误报率。
- 端到端推理延迟和掉帧情况。

当前冻结策略可作为初始配置：

- 离线分割评估阈值：0.60。
- 导航风险池化阈值：0.50。
- 风险池化：每个单元保留最近的预测动态回波。

阈值只有在真实验证集上完成校准后才能修改，测试集不能参与阈值选择。

## 9. 部署前验收清单

- [ ] 原始 bag 和元数据完整，并通过公司合规检查。
- [ ] 雷达、IMU和飞控时间戳连续且时间基准明确。
- [ ] 点级时间偏移已保留并正确使用。
- [ ] 雷达到机体的外参方向、单位和数值已确认。
- [ ] 静态墙面、地面在运动补偿后无明显重影。
- [ ] 真实四通道输入与训练输入定义完全一致。
- [ ] 真实输入统计与仿真分布完成对照。
- [ ] 首帧和历史帧状态切换正确。
- [ ] 静态场景误报满足导航安全要求。
- [ ] 动态目标召回率和速度误差达到部署要求。
- [ ] TorchScript 模型校验和与部署清单一致。
- [ ] 推理速度、显存、CPU占用和丢帧率满足机载计算平台要求。
- [ ] 已完成受控环境低速试飞，再逐步扩大飞行范围。

## 10. 推荐执行顺序

1. 固定 MID360 安装并记录尺寸、方向和设备配置。
2. 建立统一时间同步。
3. 采集平墙、空旷和全静态数据。
4. 完成外参、时间偏移和距离噪声统计。
5. 采集雷达运动及动态目标数据。
6. 按公司流程将数据放入远程数据盘。
7. 运行真实输入统计并与当前 12K v2 仿真数据对照。
8. 根据差异修改仿真器参数。
9. 生成小规模校准 pilot 并完成联合审计。
10. 确认无误后再生成最终 120K 数据或开展真实数据微调。
11. 在独立真实测试集上冻结评估。
12. 完成受控环境部署和逐级飞行验收。
