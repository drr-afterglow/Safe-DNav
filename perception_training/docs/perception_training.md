# perception_training 感知训练完整流程总结

本文档按照实际执行顺序，总结 SA-UMNet 感知模块从任务定义、数据构建、训练评估、消融实验、仿真修复到模型导出的完整过程。每一步均说明目的、实施内容、实验结果和结论。文中的“第一版 12K”表示扫描内运动修复前的数据和模型，“12K v2”表示完成逐射线扫描内运动建模后重新生成的数据和最终模型，两者不能混淆。

### 步骤一：明确感知任务与物理表示

**目的：** 明确网络究竟需要识别什么、预测什么，以及感知输出怎样服务于无人机导航，防止数据标签、网络输出和 PPO/CBF 接口采用不同的物理定义。

**内容与具体做法：** 将机体系冻结为 FLU 坐标系，即 x 轴向前、y 轴向左、z 轴向上。网络的动态目标速度监督定义为障碍物绝对平移速度旋转到当前机体系后的球坐标分量 `(v_r, v_theta, v_phi)`：`v_r > 0` 表示沿视线远离，`v_theta > 0` 表示方位角从前向左增大，`v_phi > 0` 表示向上运动。网络不直接学习无人机与障碍物的相对速度，运行时先把无人机速度投影到每个像素的局部球坐标基，再计算 `V_rel = V_abs - V_ego`。每帧点云使用逐点时间戳和 IMU 信息去畸变到扫描结束时刻；上一帧也通过位姿补偿对齐到当前机体系。真实帧间隔 `delta_t` 作为网络输入条件，参考值为 0.096 s，允许范围为 0.05–0.15 s。

**最终结果：** 训练数据、模型、运行时和下游接口使用了统一的坐标系、速度符号和时间参考。网络输出的绝对速度可以稳定转换为 PPO/CBF 所需的相对速度。

**结论：** 物理表示契约已经冻结。后续接入 ROS、PX4 或真实 MID360 时，如果外部系统使用 FRD 或 NED，必须先转换到 FLU，不能直接混用。

### 步骤二：确定 SA-UMNet 网络结构、输入输出与训练方式

**目的：** 构建一个能够利用前后帧雷达差异、完成全景逐像素动态分割、速度估计和不确定性估计，同时又足够轻量、适合机载实时推理的网络。

**内容与具体做法：** 当前 SA-UMNet 是两级对称轻量 U-Net，主通道为 `16 → 32 → 64 → 32 → 16`，参数量约 142,119。输入张量固定为 `[B,4,16,180]`，四个通道依次为：

1. `current_depth`：当前帧归一化深度；
2. `aligned_previous_depth`：经过自运动补偿、对齐到当前机体系的上一帧深度；
3. `current_return_valid`：当前帧真实有效回波掩码；
4. `aligned_previous_return_valid`：对齐后的上一帧有效回波掩码。

深度除以最大量程归一化，无回波深度填充为 1.0；有效回波通道来自真实射线命中信息，值为 0 或 1。显式回波掩码让网络能够区分“距离很远”和“根本没有有效回波”，避免把无回波误认为远距离障碍物。

网络内部按以下顺序工作：

- 第一层编码器 `enc1`：两次 SphericalConvBlock，将 4 通道变为 16 通道。该层直接处理原始全景输入，使用水平循环填充保证 `-180°/180°` 首尾相连，并利用俯仰角网格进行球面/俯仰角调制，使卷积更适合雷达全景图的空间几何。
- 第一次 MaxPool：使用 `2×2` 最大池化，把空间尺寸减半。作用是扩大感受野、降低计算量并提取更高层特征。
- 第二层编码器 `enc2`：两次标准循环卷积，将 16 通道变为 32 通道。作用是组合局部深度、回波有效性和双帧变化模式。
- 第二次 MaxPool：再次将空间尺寸减半，使网络能够观察更大范围的目标轮廓和运动关系。
- 瓶颈层 `bottleneck`：两次卷积，将 32 通道变为 64 通道。它是网络语义最集中的部分，用于融合更大范围的环境结构和动态信息。
- 第一层解码器 `up1`：双线性插值上采样，将瓶颈特征与第二层编码器的 32 通道跳跃特征拼接，再通过卷积输出 32 通道。跳跃连接恢复池化过程中丢失的空间位置和边界细节。
- 第二层解码器 `up2`：再次上采样，将特征与第一层编码器的 16 通道高分辨率特征拼接，经过球面卷积输出 16 通道。该层负责恢复到 `16×180` 原始分辨率，并保持全景接缝和俯仰方向结构。
- GroupNorm：用于稳定小批量训练，不依赖很大的 batch size。
- SiLU 激活：提供平滑非线性，有利于轻量网络训练。
- 语义头 `semantic_head`：`1×1` 卷积输出 `mask_logits [B,1,16,180]`，经 sigmoid 后表示每个像素属于动态障碍物的概率。
- 运动学头 `kinematic_head`：`1×1` 卷积输出 `velocity [B,3,16,180]`，分别预测 `v_r、v_theta、v_phi`。
- 不确定性头 `uncertainty_head`：`1×1` 卷积输出 `log_sigma [B,3,16,180]`。通过 `sigma = exp(log_sigma)` 得到三个速度分量的不确定性标准差，`log_sigma` 被限制在 -5 到 3 之间，防止数值失控。
- 时间尺度修正：速度和 sigma 都乘以 `reference_delta_t / delta_t`，使帧率发生小幅抖动时，输出仍保持物理速度单位。

网络总损失为：

```text
L_total = lambda_seg × L_seg
        + lambda_kin × L_kin
        + lambda_static × L_static
```

其中：

- `L_seg` 是 valid-aware 的 Focal Loss 与 Dice Loss 之和。Focal Loss 使用 `alpha=0.75、gamma=2.0`，提高动态少数类和难样本的权重，避免大量静态像素主导训练；Dice Loss直接优化预测区域与真实动态区域的整体重合程度；两者都只在有效回波区域计算。
- `L_kin` 是只在真实动态有效像素上计算的异方差 Laplace 负对数似然。其核心形式为 `|v_gt-v_pred|/b + log(b)`，其中 `b=sigma/sqrt(2)`。它同时训练速度和不确定性：误差大时允许预测更大 sigma，但 `log(b)` 会惩罚无条件增大不确定性的行为。
- `L_static` 是静态有效区域的速度零值正则，惩罚墙壁、地面等静态背景上的虚假速度。
- 默认三个速度分量权重相同。实验中测试过远距离动态像素加权和径向速度分量加权，但最终基线仍采用默认权重。

训练时，数据集按 shard 加载，使用 LRU 缓存和 shard-aware sampler；训练、验证、测试按完整 `scene_id` 隔离，禁止同一场景泄漏到不同集合。每个 batch 完成前向传播、复合损失计算、反向传播、优化器更新和学习率调度。每轮结束后在完整验证集累计指标，并用 `IoU + Recall - 动态速度MAE/5 - 静态虚假速度均值/5` 的综合评分选择最佳 checkpoint。checkpoint 保存模型、优化器、scheduler、scaler、随机状态和历史最佳结果，因此训练中断后可以精确恢复。完成训练后，只使用一次冻结测试集评估候选模型，随后导出 TorchScript 并做原模型与导出模型的一致性验证。

**最终结果：** 网络可以同时输出动态区域、三维绝对速度和速度不确定性；双帧信息、回波有效性和真实帧间隔均进入统一推理链路。GPU 前向、反向、FP16 AMP 单步训练、Python编译和运行时回归均通过。

**结论：** 当前结构在全景稠密预测能力、参数量和部署成本之间取得了平衡，已作为冻结的 SA-UMNet v2 结构使用。除非重新生成数据并进行完整公平实验，不应随意改变输入顺序、坐标系、输出语义或损失定义。

### 步骤三：构建 MID360 仿真数据采集器

**目的：** 在没有大量真实标注数据的情况下，生成具有精确动态掩码、速度、自运动和可见性标签的训练数据，同时尽量接近 MID360 的非重复扫描特性。

**内容与具体做法：** 感知采样与 PPO 使用的 `6×36` 固定射线接口解耦。采集器使用覆盖 `360°×59°` 视场的非重复低差异扫描近似，标称点率为 200,000 points/s，每帧约 0.096 s，仿真默认使用 5,760 条射线计算子采样。加入最小量程、随机漏点、距离噪声、Z-buffer遮挡、逐点时间偏移和扫描覆盖统计。动态球体使用加速度受限运动，无人机包含随机平移、旋转、线加速度和角加速度。采集结果保存四通道输入、动态 mask、三维速度、valid、`delta_t`、`scene_id`、自运动和补偿误差等字段，并在写盘前执行有限值、形状和物理一致性检查。

**最终结果：** 建立了能够批量生成训练、验证和测试 shard 的采集链路，并修复了 Isaac RayCaster 在手动更新无人机位姿后仍读取旧位姿的问题。

**结论：** 仿真采集器能够提供完整监督信号，但其扫描轨迹仍是工程近似，而不是 Livox 官方光机轨迹，因此真实部署前仍需要真实 MID360 统计与标定。

### 步骤四：修复噪声回波与标签不一致

**目的：** 保证网络看到的 noisy depth 与 mask、速度标签描述的是同一个实际可见回波，避免训练数据存在隐蔽错标。

**内容与具体做法：** 检查发现，早期流程在加入距离噪声和回波丢失后，标签仍可能使用干净 Z-buffer 的像素赢家。随后把静态/动态最近命中合并、距离噪声、有效回波判断、mask和速度标签统一到同一个 Z-buffer 赢家上，并在自动审计中增加 `mask/valid`、静态速度和有限值约束。

**最终结果：** 输入深度、有效回波、动态掩码和速度标签严格对齐，错误回波不会继续保留动态标签。

**结论：** 标签一致性问题得到修复，后续 pilot 和正式数据均使用新的同源赢家规则。

### 步骤五：生成四通道 Pilot 数据并验证可学习性

**目的：** 在正式采集大规模数据之前，用低成本验证数据格式、标签、可视化结果和训练链路是否正确。

**内容与具体做法：** 生成 `scene_101、scene_102、scene_103` 三个场景，每个场景500条，共1500条、6个 shard，约198 MB。检查形状、NaN/Inf、valid二值性、mask与valid关系、静态速度、场景编号和manifest一致性；生成50张随机诊断图和contact sheet进行人工检查。随后选择32个样本执行500次FP32过拟合更新，确认网络能否记住小数据集。

**最终结果：** 自动审计全部通过，人工检查未发现深度、valid、mask或速度明显错位。32样本过拟合得到 mask IoU 0.726、F1 0.841、Recall 0.870、总体速度 MAE 0.095 m/s；远距离 IoU 为0.490，静态虚假速度均值为0.290 m/s。

**结论：** 数据和训练链路具备可学习性；远距离分割与静态虚假速度被确定为后续重点问题。该pilot权重仅用于诊断，不作为正式模型。

### 步骤六：冻结数据配比并建立数据审计

**目的：** 防止正式训练集过度偏向静态或简单动态场景，并确保高速、远距离、全景接缝和强自运动样本有足够覆盖。

**内容与具体做法：** 正式数据比例冻结为纯静态25%、普通动态50%、困难动态25%。分别建立三套采集配置并各采集64条冒烟样本。新增 `audit_dataset.py`，统计静态比例、远距离动态像素、高速动态像素、接缝动态像素、大位移和大旋转覆盖，同时检查mask/valid、静态速度、有限值、场景隔离和manifest。

**最终结果：** 192条冒烟数据全部通过审计。困难场景中高速动态像素占比99.85%，大位移样本53/64、大旋转33/64、接缝动态像素3.18%；静态配置64/64均为全零mask和速度。

**结论：** 正式数据分布和最低覆盖要求得到固定，后续12K与12K v2均沿用25%/50%/25%的总体配比。

### 步骤七：建立完整感知性能指标体系

**目的：** 避免仅使用Accuracy或单一损失评价模型。动态像素远少于静态像素，即使模型把所有像素都判断为静态，Accuracy也可能很高，因此必须同时评估检测、速度、不确定性、距离分层、全景接缝和导航风险。

**内容与具体做法：** 在完整epoch上累计TP、FP、FN、TN和误差总量后统一计算指标，而不是先算每个batch再平均。指标及其含义如下：

- **Accuracy（准确率）**：`(TP+TN)/(TP+FP+FN+TN)`，表示所有有效像素中判断正确的比例。它直观但容易被大量静态像素抬高，不能单独代表动态识别能力。
- **Precision（精确率）**：`TP/(TP+FP)`，表示被网络判断为动态的像素中有多少确实是动态目标。越高说明误报越少。
- **Recall（召回率）**：`TP/(TP+FN)`，表示所有真实动态像素中有多少被发现。对安全导航尤其重要，因为低Recall意味着可能漏掉正在接近的障碍物。
- **F1**：Precision和Recall的调和平均，只有两者都较高时F1才高，用于衡量误报与漏报的综合平衡。
- **IoU（交并比）**：`TP/(TP+FP+FN)`，表示预测动态区域与真实动态区域的重叠程度，是本项目主要分割指标。
- **FPR（假阳性率）**：`FP/(FP+TN)`，表示静态像素被错误判断为动态的比例。过高会让无人机无故绕行、减速或停滞。
- **Support（样本支持量）**：某个指标实际包含的真实像素或样本数量。距离桶没有动态目标时，指标数值本身没有解释意义，必须结合support。
- **近、中、远距离Recall/IoU**：分别在0–2 m、2–5 m和5–10 m统计。0–2 m反映迫近安全，2–5 m反映主要避障区，5–10 m反映提前发现能力。
- **速度MAE**：预测与真实速度绝对误差的平均值，分别统计 `v_r、v_theta、v_phi` 和总体误差，单位m/s，数值越低越好。
- **速度RMSE**：平方误差均值开根号，对少数大误差比MAE更敏感，可发现危险的速度离群预测。
- **径向速度误差**：单独评价 `v_r`。径向速度直接反映目标接近或远离，是TTC和CBF风险判断中最重要的速度分量。
- **静态虚假速度均值**：在真实静态有效区域统计预测速度模长平均值，越低说明静态背景越稳定。
- **静态虚假速度P95**：静态速度模长的95%分位数，用于发现数量较少但幅度很大的虚假速度。
- **Laplace NLL**：同时衡量速度误差与预测sigma是否匹配。错误很大但sigma很小会受到强惩罚，sigma无条件过大也会因对数项受罚。
- **误差与sigma相关性**：检查模型在误差较大时是否也预测更大的不确定性。正相关且稳定说明不确定性具有辨识能力。
- **1 sigma覆盖率和2 sigma覆盖率**：真实误差落在预测1倍或2倍sigma范围内的比例，用于判断模型是否过度自信或过度保守；解释时采用当前Laplace分布，不能套用正态分布固定比例。
- **平均sigma**：模型总体给出的速度不确定性尺度，用于监控sigma是否整体塌缩或膨胀。
- **池化单元召回率**：包含真实动态目标的低分辨率 `6×36` 单元中，有多少在池化后仍然报告动态信息。
- **危险目标保留率/风险目标保留率**：池化最终选择的高分辨率回波是否落在真实动态或真实高风险目标上，用于发现高分辨率预测正确但降采样后危险目标丢失的问题。
- **平均Oracle风险保留**：池化选中回波的风险与该单元理论最危险真实回波风险的相对保留程度，越接近1说明越接近最优风险选择。
- **接缝IoU和Recall**：只在全景图首尾边界附近计算动态分割性能，检查跨越 `-180°/180°` 的目标是否完整。
- **首末列概率差及其误差**：衡量物理相邻的全景首列和末列是否产生人工断裂。
- **综合checkpoint评分**：`IoU + Recall - 动态速度MAE/5 - 静态虚假速度均值/5`。它只用于同一次训练中选择checkpoint，不是独立物理指标，也不用于替代冻结测试集报告。

**最终结果：** 完整评估器、距离分桶、不确定性、风险池化和接缝指标均已实现；新增标签对齐回归后共17项测试通过，RTX 4090 D上的FP16训练集成冒烟测试通过。

**结论：** 后续模型不再用Accuracy或单一IoU决定优劣，而是同时考虑动态区域、速度、静态误报、不确定性和导航风险。

### 步骤八：生成第一版12K中间数据集

**目的：** 在生成120K和训练最终模型前，用中等规模数据检验完整训练效果、场景隔离和主要性能瓶颈。

**内容与具体做法：** 生成12,000条数据，训练/验证/测试分别为8,400/1,800/1,800，共9个互斥场景、27个shard，约1.4 GB。严格按完整scene_id划分集合，避免相似轨迹泄漏。完成全量自动审计，并生成45张诊断图进行人工检查。修改训练入口，使配置能够显式指定train_roots和val_roots，避免冻结场景被二次随机切分。

**最终结果：** 静态样本25.04%，远距离动态像素24.29%，高速动态像素27.20%，接缝动态像素3.81%；审计和人工检查通过。1 epoch FP32冒烟训练成功，初始验证IoU为0.205。

**结论：** 第一版12K数据满足中规模训练条件，场景隔离和加载链路正确。

### 步骤九：完成第一版12K FP32基线和断点续训

**目的：** 获得第一个正式中规模基线，同时验证训练被中断后能否完整恢复。

**内容与具体做法：** 为 `train.py` 增加 `--resume`，恢复模型、优化器、scheduler、scaler、起始轮次、随机状态和历史最佳评分；兼容旧checkpoint的余弦学习率重建。基线先训练到40轮，再从第40轮续训至80轮，并保存第50/60/70/80轮和最终checkpoint。使用最佳验证评分checkpoint在1,800条冻结测试集上评估。

**最终结果：** 最佳为约第63轮，验证IoU 0.7463、F1 0.8547、Recall 0.8372、远距离IoU 0.5144、速度MAE 0.5079 m/s。冻结测试集IoU 0.7523、F1 0.8587、远距离IoU 0.5126、速度MAE 0.5086 m/s、静态虚假速度0.1016 m/s、接缝IoU 0.7641。第80轮checkpoint包含完整恢复状态。

**结论：** 第一版正式训练成功，断点续训可靠；主要短板仍是远距离动态目标和约0.5 m/s的总体速度误差。

### 步骤十：完成 AMP 与 FP32 对照训练

**目的：** 判断自动混合精度能否在保持精度的同时加快训练或减少显存，为后续更大规模训练选择计算模式。

**内容与具体做法：** 使用相同12K数据、相同训练轮数和评估方式完成80轮AMP对照，只改变数值精度；在冻结测试集比较IoU、F1、速度MAE，同时公平计时并测量峰值显存。

**最终结果：** AMP最佳为第59轮，测试IoU 0.7537、F1 0.8595、速度MAE 0.5078 m/s，与FP32基本等价。AMP每轮5.795 s，FP32每轮5.739 s，AMP慢约1.0%；峰值显存从2656.8 MB降至2280.8 MB，节省14.2%。

**结论：** AMP不会明显损害精度且可以节省显存，但当前小型网络在RTX 4090 D上没有速度收益。标准基线继续使用FP32，显存受限时可启用AMP。

### 步骤十一：建立并选择导航风险池化策略

**目的：** 将网络的 `16×180` 高分辨率输出压缩成PPO使用的 `6×36` 时，保留真正影响碰撞安全的回波，而不是仅保留概率最高但距离较远的目标。

**内容与具体做法：** 先修复旧Danger Pool指标未约束有效回波的问题，再建立基于真实距离、径向接近速度、TTC和CBF的风险定义。数据契约新增 `ego_velocity_body_mps`，用于从绝对速度严格计算相对速度。采集独立运动风险验证集和测试集各1,800条，普通动态和困难动态各900条，场景完全隔离。比较最高动态概率、speed×sigma和最近预测动态回波等策略，并只在验证集选型、冻结测试集确认。

**最终结果：** 全样本冻结风险测试中，最近距离策略的风险目标保留率为0.9139、平均Oracle风险保留为0.8389；旧speed×sigma策略只有0.7836和0.6266。输出一致性回归通过。

**结论：** 运行时冻结为每个 `6×36` 单元保留最近的预测动态回波，因为该策略最稳定地保留了迫近风险。

### 步骤十二：完成远距离分割损失消融

**目的：** 验证将5–10 m远距离动态正样本的分割损失提高2倍，能否改善提前发现能力。

**内容与具体做法：** 保持网络、数据、训练轮数和其他损失不变，只把远距离动态正样本的Focal权重设为2，训练80轮，在验证集选择最佳checkpoint后使用同一冻结测试集评估，并比较分割、误报和风险池化。

**最终结果：** 最佳为第62轮。5–10 m IoU从0.5126提升到0.5199，Recall从0.6181提升到0.6438；总体IoU从0.7523微降至0.7506，FPR从0.0147升至0.0168；运动风险目标保留率从0.9139微升到0.9167。

**结论：** 远距离2倍加权确实提高远距离召回，但代价是误报增加和总体IoU轻微下降，因此不覆盖默认基线，只保留为高召回备选。

### 步骤十三：完成径向速度损失消融

**目的：** 验证把径向速度 `v_r` 的损失权重提高2倍，能否降低对TTC和CBF最关键的径向速度误差。

**内容与具体做法：** 保持其他设置不变，仅提高径向速度分量权重，训练80轮并在同一冻结测试集比较径向、切向和总体速度误差，同时检查分割与风险指标的变化来源。

**最终结果：** 最佳为第63轮。径向速度MAE从0.6790增加到0.6815 m/s，两个切向分量和总体速度MAE也恶化；虽然IoU和风险保留有小幅提高，但主要来自检测率变化，而不是速度预测改善。

**结论：** 该消融没有达到降低径向速度误差的目的，不采用。

### 步骤十四：完成第一版候选模型选择

**目的：** 在FP32基线、远距离2倍和径向速度2倍模型之间确定默认模型，避免根据单个有利指标主观选型。

**内容与具体做法：** 对候选模型使用相同验证集校准阈值，再在冻结测试集比较总体IoU、F1、远距离IoU、速度MAE、FPR和风险保留。远距离2倍模型在验证集选择阈值0.60后再做测试。

**最终结果：** 远距离2倍模型测试IoU/F1为0.7517/0.8582，远距离IoU 0.5160，速度MAE 0.5127 m/s；基线分别为0.7523/0.8587、0.5126和0.5086 m/s。

**结论：** 第一版默认模型确定为FP32基线最佳轮次，远距离2倍仅作为高召回备选，径向速度2倍淘汰。

### 步骤十五：执行扩大到120K前的技术审查

**目的：** 在花费大量时间和存储生成120K数据之前，检查仿真物理、标签质量、覆盖率、磁盘、真实传感器参数和训练链路是否已经具备放大条件。

**内容与具体做法：** 审查数据覆盖与场景隔离、标签约束、MID360扫描方式、逐点时间、无人机和目标在96 ms扫描期间的运动、磁盘估算、真实MID360点数/噪声/漏点、外参和时间同步。预计120K约需13.4 GiB。

**最终结果：** 覆盖和标签审计通过，但发现采集器虽然生成逐点时间偏移，整帧仍使用同一传感器姿态和动态球位置求交，未真正模拟扫描内运动；真实MID360标定也缺失。数据盘最初余量不足，扩容后达到100 GB、剩余约73 GB，容量阻断解除。

**结论：** 120K暂不放行。扫描内运动被确定为必须先修复的核心阻断项，真实MID360标定则作为最终真实部署和最终数据分布校准的重要任务。

### 步骤十六：修复逐射线扫描内运动仿真

**目的：** 消除一帧96 ms内无人机和动态目标运动造成的系统性仿真错误，避免模型学习不真实的双帧变化模式。

**内容与具体做法：** 根据每条射线相对扫描结束时刻的负时间偏移，回推传感器位置和姿态，同时回推动态球体位置；计算包含无人机线速度、角速度、线加速度、角加速度以及动态球速度和加速度。静态地形求交、动态球求交、最近命中合并、距离噪声和有效回波判断全部改用逐射线原点。每个世界命中点最终统一变换到扫描结束时刻的机体系。mask、速度标签和noisy depth继续共享同一个Z-buffer赢家。

**最终结果：** 传感器运动、动态球运动和组合运动三类解析回归通过，Python语法和纯PyTorch检查通过；8条Isaac冒烟数据自动审计 `passed=true`、`validation_errors=[]`。

**结论：** 扫描内运动的主要物理缺陷已修复，可以生成v2数据重新训练。当前仍采用扫描期内常加速度近似，尚未模拟真实IMU噪声和更高阶连续轨迹。

### 步骤十七：生成并审查 v2 Pilot 数据

**目的：** 在重新生成12K数据前，确认扫描内运动修复没有引入新的坐标、遮挡、标签或回波错误。

**内容与具体做法：** 生成1500条、6个互斥场景：静态5101/5102、普通动态5201/5202、困难动态5301/5302，每场景250条。执行联合审计，生成36张随机诊断图和contact sheet，并进行人工检查。

**最终结果：** 静态样本33.33%，远距离动态像素24.28%，高速动态像素39.14%，接缝动态像素3.36%，大位移样本41.93%，大旋转样本32.13%；`validation_errors=[]`，人工检查无明显问题。

**结论：** v2采集链路通过小规模验证，可以安全扩展到12K中间规模。

### 步骤十八：生成 12K v2 数据集

**目的：** 使用修复后的逐射线运动仿真重新建立公平训练集，验证物理修复是否真正提升模型在正确数据分布上的表现。

**内容与具体做法：** 生成训练/验证/测试为8,400/1,800/1,800的12K v2数据，使用9个完全隔离场景：训练6101/6201/6301，验证7101/7201/7301，测试8101/8201/8301；静态/普通/困难保持25%/50%/25%。执行全量数据审计和覆盖率检查。

**最终结果：** 全量审计通过，`validation_errors=[]`；远距离动态像素约24.11%，高速动态像素约23.82%。数据保存在 `/root/autodl-tmp/NavRL_perception_intermediate_12k_v2`。

**结论：** 12K v2成为当前最终模型的正式训练、验证和冻结测试数据基础。

### 步骤十九：训练 12K v2 FP32 最终基线

**目的：** 在扫描内运动修复后的数据上重新训练网络，并与旧模型在完全相同的v2测试集上公平比较。

**内容与具体做法：** 使用冻结的SA-UMNet结构、默认复合损失和FP32训练80轮；依据完整验证集综合评分保存最佳checkpoint，再在v2冻结测试集评估。旧模型也在同一个v2测试集上重新评估，避免跨数据集比较。

**最终结果：** 最佳为第64轮，综合评分1.484766。阈值0.50时，冻结测试集Accuracy 0.96753、IoU 0.74671、F1 0.85499、Precision 0.85740、Recall 0.85259、FPR 0.01793、远距离IoU 0.53226、速度MAE 0.51918 m/s、静态虚假速度0.09042 m/s。旧模型在同一v2测试集上的IoU只有0.66288，新模型达到0.74671；FPR从0.03389下降到0.01793，远距离、速度、静态假速度、接缝和风险保留也得到改善。最佳权重位于 `/root/autodl-tmp/NavRL_perception_intermediate_12k_v2/runs/baseline_fp32/saumnet_best.pt`。

**结论：** 新模型在正确模拟扫描内运动的数据上显著优于旧模型，证明逐射线运动修复是有效且必要的。该第64轮模型成为当前冻结的最佳模型。

### 步骤二十：校准 v2 动态掩码阈值

**目的：** 将连续动态概率转换为0/1掩码时选择有数据依据的阈值，在Recall和误报之间取得平衡，避免默认使用0.50而未经验证。

**内容与具体做法：** 仅在验证集粗扫0.30–0.75，再细扫0.56–0.64，根据IoU/F1选择阈值；确定阈值后在冻结测试集只评估一次，避免用测试集调参。

**最终结果：** 验证集最优阈值为0.60，IoU 0.751219、F1 0.857938。冻结测试集阈值0.60时，Accuracy 0.96858、IoU 0.75023、F1 0.85729、Precision 0.87471、Recall 0.84056、FPR 0.01523、远距离IoU 0.52908。

**结论：** 0.60具有更高Precision和更低FPR，适合离线分割评估；0.50保留更多动态目标，可能更适合安全敏感的导航风险池化。

### 步骤二十一：比较 0.50 与 0.60 的风险池化表现

**目的：** 判断离线分割最优阈值是否也适合导航。导航更关注危险目标不能丢失，因此不能仅凭总体IoU决定运行时阈值。

**内容与具体做法：** 在独立运动风险数据 `/root/autodl-tmp/NavRL_motion_risk_3d` 上，固定最近动态回波池化策略，只改变mask阈值，比较冻结测试集风险目标保留率和平均Oracle风险保留。

**最终结果：** 阈值0.50的风险目标保留率为0.91915、平均Oracle风险保留为0.84330；阈值0.60分别为0.91723和0.84155。

**结论：** 最终采用双阈值：离线分割标准模式使用0.60，导航风险池化安全模式使用0.50。运行时默认风险阈值冻结为0.50。

### 步骤二十二：导出模型并验证运行时一致性

**目的：** 将训练checkpoint转换为无需训练代码即可加载的部署模型，并确认导出不会改变输出、首帧逻辑或导航观测格式。

**内容与具体做法：** 把最佳第64轮模型导出为TorchScript，生成部署清单和SHA256校验值。使用相同输入比较PyTorch与TorchScript的mask、velocity和log_sigma；执行两帧GPU运行时回归，检查第一帧中性动态输出、第二帧历史有效、静态和动态池化形状、有限值和显式阈值参数。

**最终结果：** TorchScript与PyTorch三头输出逐元素一致；首帧 `history_valid=false`，第二帧为true；静态输出 `[B,1,6,36]`，动态输出 `[B,5,6,36]`，输出范围正常。部署模型位于 `/root/autodl-tmp/NavRL_perception_intermediate_12k_v2/deploy/saumnet_v2_best_ts.pt`，部署清单位于同目录 `deployment_manifest.yaml`。TorchScript SHA256为 `08aed4849714f92e184903a41ed8625825004c0ba52e0b313a3ccb0e9f40d8a9`。

**结论：** 当前最佳模型已经完成保存、导出和模型级运行时验证，可以进入NavRL导航闭环集成阶段。

### 步骤二十三：整理真实 MID360 数据准备与标定任务

**目的：** 为未来实际无人机部署消除仿真与真实雷达之间的输入分布差异，而不是为了重新保存当前模型。

**内容与具体做法：** 规划采集真实MID360原始bag、点级时间偏移、反射强度、IMU、飞控位姿和场景元数据；后续需要完成雷达到机体的外参、雷达/IMU/飞控时间同步、距离噪声、漏点率、点数、扫描覆盖率、回波掩码和四通道输入分布统计。相关操作已经整理到 `docs/MID360_REAL_DEPLOYMENT_CALIBRATION_GUIDE.md`。数据只能通过公司批准的合规方式进入远程服务器，严格禁止从本地上传任何文件或代码。

**最终结果：** 当前远程服务器尚未发现真实MID360 bag、真实点云或标定文件，因此没有执行真实统计与标定。

**结论：** 真实MID360任务暂缓到实际无人机部署阶段。若未来恢复，应从数据合规检查、静态标定数据验收、外参和时间同步开始。

### 步骤二十四：当前成果与下一阶段

**目的：** 明确目前已经完成的范围，防止把“模型级感知验证完成”误认为“整套无人机导航系统已经完成”。

**内容与具体做法：** 当前已冻结SA-UMNet v2结构、四通道输入、三头输出、复合损失、12K v2数据、最佳第64轮FP32模型、离线阈值0.60、导航风险阈值0.50、最近动态回波池化策略、TorchScript和部署清单。下游 `training_net2_reward_cbf2` 已支持五通道动态观测 `[depth, v_r_rel, v_theta_rel, v_phi_rel, sigma]`，但PPO环境目前主要仍使用仿真真值感知代理，旧三通道PPO checkpoint也不兼容当前五通道接口。

**最终结果：** 感知数据生成、训练、评估、消融、物理修复、阈值校准和模型导出已经完成；尚未完成真实网络到PPO/CBF的端到端闭环接入，120K最终训练和真实MID360验证也尚未进行。

**结论：** 在真实标定暂缓的情况下，下一步应把冻结的SA-UMNet v2 TorchScript接入NavRL导航闭环，先进行少量冒烟测试，再在静态、普通动态和困难动态场景中对比导航成功率、碰撞率、风险目标保留、路径效率和实时推理性能。闭环验证通过后，再决定是否值得扩大到120K。
