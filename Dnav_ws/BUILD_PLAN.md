# Safe-DNav ROS1 / Gazebo 构建规划

## 1. 项目目标

在 `/home/amo/Safe-DNav/Dnav_ws` 中构建一个完全独立的 ROS1 Noetic + Gazebo 导航工作空间，部署当前已经训练完成的：

- 感知网络：SA-UMNet v2
- 策略网络：`training_net2_SAMnet_reward_cbf` 对应的最终完整策略

系统最终形成以下闭环：

```text
Gazebo 传感器与无人机状态
        ↓
感知预处理 → SA-UMNet 感知推理 → 策略输入张量
        ↓
PPO 策略推理 → 世界坐标系三轴目标速度
        ↓
坐标转换与安全门控 → TwistStamped
        ↓
复用的 NavRL Gazebo 速度控制器
        ↓
无人机力和力矩 → Gazebo 无人机运动
```

仿真闭环通过后，再逐步迁移到 PX4 SITL 和真实无人机。

## 2. 已确认并修正的核心接口

### 2.1 策略输出

策略的正式输出是三维线速度，不是四维电机命令：

```text
[vx, vy, vz]
```

训练配置中的速度范围为：

```text
vx, vy, vz ∈ [-3.0, 3.0] m/s
```

策略内部首先生成机体系三维速度，然后根据当前无人机四元数转换为世界坐标系速度。因此，部署节点对外提供的标准输出定义为：

```text
世界坐标系目标速度 v_world = [vx_world, vy_world, vz_world]
```

部署时必须完整复现训练代码中的动作归一化、`[-3, 3] m/s` 缩放和四元数旋转，不能直接把 Beta 分布输出当成速度。

### 2.2 与参考 ROS1 控制器的关系

`/home/amo/Safe-DNav/ros1/uav_simulator` 中的 Gazebo 控制器可以复用。其输入为：

```text
消息类型：geometry_msgs/TwistStamped
参考话题：/CERLAB/quadcopter/cmd_vel
```

控制器实际采用的速度坐标约定为：

- `twist.linear.x`：无人机当前偏航坐标系下的前向速度。
- `twist.linear.y`：无人机当前偏航坐标系下的侧向速度。
- `twist.linear.z`：世界坐标系竖直速度。
- `twist.angular.z`：偏航角速度；当前策略不输出该量，默认置零或由独立航向控制逻辑生成。

因此，策略的世界系速度不能未经转换直接发送给该控制器。控制适配节点需要执行：

```text
[vx_body_yaw, vy_body_yaw] = Rz(yaw)^T · [vx_world, vy_world]
vz_cmd = vz_world
```

这与参考项目 `navigation_runner/scripts/navigation.py` 的处理方式一致。适配完成后，策略输出与现有控制器接口是兼容的，不需要修改策略输出维度，也不需要重新训练。

### 2.3 控制器复用范围

从参考项目复制并独立维护以下实现：

- `quadcopterPlugin` Gazebo 插件。
- `PIDController` 实现。
- 无人机 URDF、惯性参数和基础网格资源。
- 必需的起飞、降落、重置、里程计与状态发布逻辑。
- 已验证的速度环、姿态环以及推力/力矩施加逻辑。

复制后需要完成包名、库名、资源路径、节点名、话题名和 launch 文件的 `dnav_*` 化，禁止运行时引用原 `/home/amo/Safe-DNav/ros1` 目录。

## 4. ROS 节点与接口规划

### 4.1 感知节点 `dnav_perception_node`

输入：

- Gazebo 360° 激光雷达/深度扫描数据。
- 当前帧时间戳。
- 上一帧扫描和用于帧间对齐的无人机位姿。

网络输入必须与训练保持一致：

```text
shape: (B, 4, 16, 180)
channel 0: 当前帧归一化距离
channel 1: 对齐到当前坐标系的上一帧距离
channel 2: 当前帧 return-valid
channel 3: 上一帧 return-valid
```

固定约束：

- 水平视场：360°。
- 垂直视场：`[-7°, 52°]`。
- 最大距离：10 m。
- 坐标系：机体系 FLU。
- 参考帧间隔：0.096 s。
- 合法帧间隔：`[0.05, 0.15] s`。

网络输出经过训练工程中的几何和后处理逻辑生成：

```text
lidar_static:  (1, 6, 36)
lidar_dynamic: (5, 6, 36)
```

动态特征通道为：

```text
[depth, v_r_rel, v_theta_rel, v_phi_rel, sigma]
```

ROS 传输优先使用带时间戳的自定义消息；早期联调阶段可以使用标准数组消息，但正式闭环前必须加入 shape、dtype、有限值和时间戳校验。

### 4.2 策略节点 `dnav_policy_node`

输入：

```text
state:         (13,)
lidar_static:  (1, 6, 36)
lidar_dynamic: (5, 6, 36)
```

`state` 的字段顺序、归一化、坐标系和训练时定义必须逐项复现，不能只保证长度一致。节点加载 `policy_best.pt` 后输出：

```text
geometry_msgs/Vector3Stamped
frame_id: map（或最终统一的世界坐标系）
vector: [vx_world, vy_world, vz_world]
```

策略推理节点只负责忠实复现网络前向过程，不在节点内部隐藏额外限速、避障或控制器逻辑，便于与训练代码做数值回归。

### 4.3 控制适配节点 `dnav_velocity_controller_node`

输入：

- 策略输出的世界系三轴速度。
- 无人机里程计与姿态。
- 起飞状态、急停状态和导航使能状态。

处理：

1. 检查策略命令和里程计是否超时。
2. 检查速度是否含 `NaN/Inf`。
3. 对世界系水平速度进行偏航坐标变换。
4. 执行速度、加速度和变化率限制。
5. 根据飞行状态执行使能、悬停或停止逻辑。
6. 发布控制器要求的 `TwistStamped`。

输出：

```text
geometry_msgs/TwistStamped
twist.linear = [vx_body_yaw, vy_body_yaw, vz_world]
twist.angular.z = 0（初始版本）
```

建议在新工作空间中使用 `/dnav/uav/cmd_vel`，通过插件参数或 launch remap 对接，避免继续硬编码参考项目的 `/CERLAB` 命名。

### 4.4 Gazebo 控制插件

底层插件接收 `TwistStamped`，通过水平速度环、垂直速度环、姿态环和偏航角速度环计算力与力矩，并施加到 Gazebo 无人机模型。

插件需要补充的部署安全功能：

- 命令超时后自动进入零水平速度和安全垂直策略。
- 控制输入限幅。
- 可配置 PID 参数和话题名，移除不必要的硬编码。
- 起飞、降落、重置后的积分项清零。
- 仿真暂停或时间回退后的状态重置。

`dnav_controller` 已新增 C++ 制动感知安全过滤器：先将策略水平速度限制到 0.5 m/s，再由 `v·t_latency + v²/(2a) <= clearance` 生成障碍半平面；通过凸多边形裁剪和一次全局投影保证结果同时满足全部约束且与扫描顺序无关。当控制屏障投影因策略正对障碍而退化为停车，或确定性 Beta 均值在稠密观测下退化为近零速度时，在同一安全可行域内选择目标进展最大的速度。节点对策略、里程计、扫描和动态感知执行超时检查，并保留控制器下游超时保护。`simple_box_crossing` 最终三次独立运行 3/3 到达，耗时 21.10/21.22/22.24 s，SPL 0.805/0.801/0.814，最小静态间距 0.490/0.509/0.494 m。稠密静态 `room_diagonal` 在严格校验生成位置后也完成 3/3，到达时间 34.20/35.06/35.02 s，SPL 0.895/0.875/0.886，最小静态间距 0.508/0.552/0.575 m。

单动态障碍阶段修正了 `tunnel_dynamic_1.world` 中行人只有 2 cm 贴地碰撞片、无法形成航空器接触真值的问题。有效基线随即复现迎面动态碰撞。过滤器随后接入 `lidar_dynamic` 的相对径向速度和不确定度，恢复保守障碍径向速度，并针对当前单目标门槛把同一人体的多像素估计聚合为最近动态约束，避免相关噪声产生空可行域。`tunnel_single_dynamic_head_on` 三次全新进程运行 3/3 到达，耗时 19.28/23.80/24.98 s，SPL 0.942/0.834/0.805，最小原始间距 0.553/0.535/0.514 m，最小动态间距 0.638/0.622/0.529 m。评测器同时强制校验 world、spawn position 和 spawn yaw，错误 world、起点及碰撞体结果均保留审计但排除统计。

多动态障碍门槛（2026-09-18）仍未通过。三行人场景已修正碰撞体并加入正式配置；诊断过程中实现了空间连通簇合并、最多三目标的短时关联/径向外推/平滑、将 2σ 不确定度仅用于提前触发制动包络、以及严格可行域为空时的最小违反逃逸。当前已有测试结果汇总为 64/64。`multi_feasible01` 曾成功到达，但重复运行仍会与 person1/person2 碰撞；最新 `multi_response_margin01` 在 14.66 s 与 person1 接触，因此不得记为通过。现有证据表明剩余缺口是部署过滤器丢弃了训练动态观测中的切向速度，无法对交叉轨迹做短时二维碰撞预测。下一步必须保留完整水平障碍速度并加入预测约束，然后重新执行单动态回归和三动态 3/3 门槛。原始结果保存在 `evaluation_results/2026-09-17` 与 `evaluation_results/2026-09-18`。

## 6. 安全策略

系统至少实现以下保护：

- 感知输入超时：禁止继续使用旧感知结果。
- 策略输出超时：停止更新有效速度命令。
- 里程计超时：立即退出自主导航控制。
- `NaN/Inf` 检查：任一关键张量异常时阻断输出。
- 速度限幅：水平与垂直速度独立配置。
- 加速度/变化率限制：避免速度命令阶跃。
- 高度上下限：接近边界时覆盖策略的危险垂直命令。
- 急停：最高优先级覆盖所有自主命令。
- 起飞/降落状态机：策略只在飞行稳定并获得导航使能后接管。
- 诊断话题：持续发布当前状态、超时、限幅和故障原因。

安全策略在仿真中也必须启用，不能留到真机阶段才实现。

## 7. 独立性要求

`Dnav_ws` 和 `/home/amo/Safe-DNav/ros1` 必须满足：

- 不共享 catkin `build` 或 `devel`。
- 不在 `CMakeLists.txt`、`package.xml`、Python path、launch 或配置中引用原目录。
- 复制的代码和资源全部进入 `Dnav_ws/src` 对应的新包。
- 所有包名、节点名和插件库名使用 `dnav_*` 命名空间。
- 所有模型、权重和参数使用新工作空间内路径或 ROS package 路径解析。
- 完成后通过临时隔离原 `ros1` 目录进行独立性验收。

只有在以下条件全部满足后，才可以按用户后续明确指令移除原 `ros1` 参考目录：

1. 新工作空间可从干净终端独立编译。
2. Gazebo、感知、策略和控制闭环可独立启动。
3. 端到端基础场景通过。
4. 复制来源和必要许可证已保留。
5. 用户明确确认删除。

## 8. 推荐实施顺序

```text
接口基线
→ 独立 catkin 包
```
